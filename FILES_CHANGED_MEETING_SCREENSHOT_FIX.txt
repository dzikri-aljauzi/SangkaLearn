TECHNICAL NOTES
==============================================================

WHY 2 PARAMETERS NEEDED:
- Route structure: courses/{course:slug}/meetings/{meeting}/screenshots/upload
- Laravel passes ALL route parameters to controller IN ORDER
- First parameter: $course (course slug)
- Second parameter: $meeting (meeting ID)
- If controller only accepts 1 parameter, it receives the first one (course slug)

WHY MANUAL RESOLUTION:
- Automatic model binding doesn't work well with nested routes + multiple params
- Manual resolution ensures correct parameter is used
- findOrFail() still throws 404 if meeting not found
- No changes needed to route definition

METHODS NOT CHANGED:
- delete() - Uses /screenshots/{screenshot} (only 1 additional param)
- updateNotes() - Uses /screenshots/{screenshot}/notes (only 1 additional param)
- Both use automatic model binding successfully
