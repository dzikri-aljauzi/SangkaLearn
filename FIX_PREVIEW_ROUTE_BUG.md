# Fix Preview Route Bug - Documentation

## Bug Report

**Issue:** Ketika klik icon Eye untuk preview di `/admin/courses`, halaman hanya refresh dan tetap berada di route yang sama, tidak redirect ke preview page.

**Expected Behavior:** Seharusnya redirect ke `/admin/courses/{slug}/preview` dan menampilkan student view dengan preview banner.

**Actual Behavior:** Halaman hanya refresh, tetap di `/admin/courses`

---

## Root Cause Analysis

### Masalah yang Ditemukan:

1. **Route Parameter Binding Tidak Eksplisit**
   - Route definition menggunakan `{course}` tanpa explicit binding
   - Laravel tidak tahu apakah harus bind by ID atau slug
   - Course model memiliki `getRouteKeyName()` yang return 'slug', tapi tidak cukup tanpa explicit binding

2. **Route Configuration**
   ```php
   // SEBELUM (Bermasalah)
   Route::get('/courses/{course}/content', ...)
   Route::get('/courses/{course}/preview', ...)
   ```

   **Masalah:**
   - Tidak jelas parameter menggunakan slug atau ID
   - Ziggy route helper mungkin generate URL yang salah
   - Implicit binding bisa confuse dengan route lain

### Verifikasi Masalah:

**Route terdaftar dengan benar:**
```bash
php artisan route:list | grep preview
# Output: admin/courses/{course}/preview .... admin.courses.preview
```

**Frontend call sudah benar:**
```javascript
// resources/js/Pages/Admin/Courses/Index.jsx
href={route('admin.courses.preview', course.slug)}  // ✓ CORRECT
```

**Model binding sudah benar:**
```php
// app/Models/Course.php
public function getRouteKeyName()
{
    return 'slug';  // ✓ CORRECT
}
```

**Tapi masih tidak bekerja karena:**
- Route parameter tidak eksplisit menggunakan slug binding
- Perlu explicit binding: `{course:slug}`

---

## Solution Implemented

### 1. Fix Route Definition dengan Explicit Binding

**File:** `routes/web.php`

**BEFORE (Line 386, 389):**
```php
// Course Content Management
Route::get('/courses/{course}/content', [App\Http\Controllers\Admin\CourseContentController::class, 'show'])->name('courses.content');

// Course Preview Route
Route::get('/courses/{course}/preview', [App\Http\Controllers\Admin\CourseController::class, 'preview'])->name('courses.preview');
```

**AFTER:**
```php
// Course Content Management
Route::get('/courses/{course:slug}/content', [App\Http\Controllers\Admin\CourseContentController::class, 'show'])->name('courses.content');

// Course Preview Route
Route::get('/courses/{course:slug}/preview', [App\Http\Controllers\Admin\CourseController::class, 'preview'])->name('courses.preview');
```

**Changes:**
- `{course}` → `{course:slug}` ✓ Explicit slug binding
- Laravel sekarang tahu pasti menggunakan slug untuk route model binding
- URL generation akan konsisten menggunakan slug

**Purpose:**

- Ensure route helper di frontend generate URL yang benar
- Sync backend routes dengan frontend route helper

### 3. Rebuild Frontend Assets

**Purpose:**

## Technical Details

### Explicit Route Model Binding

**Syntax:** `{parameter:column}`

**Examples:**
```php
// By ID (default)
Route::get('/users/{user}', ...);  // Uses 'id'

// By Slug (explicit)
Route::get('/courses/{course:slug}', ...);  // Uses 'slug'

// By UUID
Route::get('/posts/{post:uuid}', ...);  // Uses 'uuid'
```

**Benefits:**
- ✓ Clear and explicit
- ✓ No ambiguity
- ✓ Better for URL generation
- ✓ Consistent behavior
- ✓ Works with Ziggy route helper

### Why getRouteKeyName() Wasn't Enough?

```php
// Model definition
public function getRouteKeyName()
{
    return 'slug';
}
```

**Limitations:**
- Only affects implicit binding when NO explicit binding specified
- Doesn't guarantee Ziggy will use it for URL generation
- Better to be explicit in route definition

**Best Practice:**
```php
// Combine both for clarity
Route::get('/courses/{course:slug}', ...);  // Explicit in route

// AND
public function getRouteKeyName()  // Backup for other cases
{
    return 'slug';
}
```

## Root Cause Summary

### Why It Wasn't Working:

1. **Implicit Binding Ambiguity**
   - Route: `{course}` tanpa type hint
   - Model has `getRouteKeyName()` = 'slug'
   - But Ziggy doesn't always respect this for URL generation

2. **URL Generation Issue**
   - Frontend: `route('admin.courses.preview', course.slug)`
   - Ziggy generates: `/admin/courses/{value}/preview`
   - But without explicit binding, Laravel might expect ID
   - Result: 404 atau redirect ke wrong page

3. **Lack of Explicit Declaration**
   - Laravel prefers explicit over implicit
   - `{course:slug}` is clearer than relying on model method

### Why It's Working Now:

1. **Explicit Slug Binding**
   - Route: `{course:slug}` ✓ Clear and explicit
   - Laravel knows to use slug column
   - No ambiguity

2. **Consistent URL Generation**
   - Ziggy now generates correct URLs
   - `/admin/courses/introduction-to-laravel/preview` ✓
   - Matches what Laravel expects

3. **Route Model Binding**
   - `{course:slug}` automatically finds Course by slug
   - Controller receives Course model instance
   - No manual lookup needed

## Prevention for Future

### Best Practices Checklist:

When adding new routes with model binding:

- [ ] Use explicit binding: `{model:column}`
- [ ] Don't rely solely on `getRouteKeyName()`
- [ ] Test route generation with Ziggy
- [ ] Verify route list after adding routes
- [ ] Test actual navigation in browser
- [ ] Check URL format matches expectation

### Example Template:

```php
// ✅ GOOD - Explicit binding
Route::get('/items/{item:slug}', [ItemController::class, 'show']);

// ❌ BAD - Implicit binding (ambiguous)
Route::get('/items/{item}', [ItemController::class, 'show']);

// ✅ GOOD - Clear by ID
Route::get('/items/{item:id}', [ItemController::class, 'show']);
```
